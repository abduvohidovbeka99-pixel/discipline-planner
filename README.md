# Ежедневник — дисциплина

Трекер привычек, тренировки с анимированными фигурами, питание для набора массы, награды, мотивация и книги.
Это React-версия прототипа [`legacy/original.html`](legacy/original.html): функционал, тексты и стиль перенесены 1-в-1.

- React 18 + TypeScript + Vite
- Zustand (данные сохраняются в `localStorage` под старым ключом `habit-tracker-v1`, в старом формате)
- PWA: ставится на телефон, работает офлайн
- Vitest для расчётов, миграций и хранилища
- Бэкенда нет

## Запуск

Нужен Node.js 20+ (проверено на 22).

```bash
npm install
```

```bash
npm run dev
```

Откройте http://localhost:5173.

| Команда | Что делает |
| --- | --- |
| `npm run dev` | dev-сервер с горячей перезагрузкой |
| `npm test` | тесты (Vitest) |
| `npm run build` | проверка типов + продакшн-сборка в `dist/` |
| `npm run preview` | локальный просмотр собранной версии (с service worker) |

Открыть с телефона в той же Wi-Fi-сети: `npm run dev -- --host`, затем зайти на адрес вида `http://192.168.x.x:5173`.
Установка PWA и офлайн-режим работают только по HTTPS, поэтому для установки на телефон приложение нужно задеплоить (см. ниже).

## Перенос данных из старой версии

Новое приложение открывается по другому адресу и не видит `localStorage` старого HTML-файла. Данные переносятся файлом:

1. Откройте старый `legacy/original.html` в том же браузере, где были ваши отметки.
2. На главном экране под иконками нажмите **«⬇ Экспорт данных»**. Скачается `discipline-backup-ГГГГ-ММ-ДД.json`
   (на телефоне откроется меню «Поделиться»; содержимое также копируется в буфер обмена).
3. В новом приложении нажмите шестерёнку на главной → **Настройки** → **«Импорт из файла»**
   или **«Вставить текст»** (если удобнее вставить JSON из буфера).
4. Проверьте сводку (привычки, отметки, вес…) и нажмите **«Заменить данные»**.

Формат файла совпадает со старым ключом `habit-tracker-v1` плюс поле `schemaVersion`.
Поэтому экспорт новой версии тоже можно загрузить обратно в старую.

## Установка на телефон

После деплоя откройте адрес сайта:

- **iPhone (Safari):** «Поделиться» → «На экран „Домой“».
- **Android (Chrome):** меню ⋮ → «Установить приложение» (или баннер «Добавить на главный экран»).

Приложение откроется без адресной строки, с тёмной темой `#14111b`, и будет работать без интернета.
Обновления подтягиваются автоматически при следующем запуске с интернетом.

> Данные хранятся только на устройстве. Периодически делайте экспорт в Настройках: если удалить PWA или очистить данные сайта, отметки пропадут.

## Деплой

### Vercel
1. Залейте репозиторий на GitHub.
2. На vercel.com → **Add New Project** → выберите репозиторий. Настройки подхватятся из `vercel.json` (сборка `npm run build`, папка `dist`, SPA-rewrites).
3. **Deploy**.

### Netlify
1. На app.netlify.com → **Add new site → Import an existing project** → репозиторий.
2. Настройки берутся из `netlify.toml` (папка `dist`, редирект `/* → /index.html`).

### GitHub Pages
1. В репозитории: **Settings → Pages → Source: GitHub Actions**.
2. Сделайте push в `main`. Workflow `.github/workflows/deploy-pages.yml` запустит тесты, соберёт сайт с `BASE_PATH=/<имя-репо>/` и создаст `404.html`, чтобы прямые ссылки вроде `/repo/tracker` открывались.
3. Сайт будет доступен по адресу `https://<user>.github.io/<repo>/`.

Для любого другого хостинга, где сайт живёт в подпапке, используйте `BASE_PATH=/подпапка/ npm run build`.
Сервер должен отдавать `index.html` для всех неизвестных путей.

### Данные и миграции

- Модель описана в `src/store/types.ts`. Месяцы хранятся под ключом `"ГГГГ-М"`, где месяц считается **с нуля**, как в оригинале: ноябрь 2026 — это `"2026-10"`.
- `schemaVersion` — версия формата. Старые данные считаются версией 0. Миграция `0 → 1` повторяет то, что прототип делал при загрузке: подставляет значения по умолчанию, добавляет привычки «Подтягивания»/«Брусья» и чистит мусорные поля.
- Чтобы добавить новую версию формата: увеличьте `SCHEMA_VERSION` и допишите функцию в массив `MIGRATIONS` в `migrations.ts`.

### Под Capacitor и синхронизацию

- Всё хранилище проходит через `KVBackend` в `store/storage.ts`. Для Capacitor достаточно реализовать его на `@capacitor/preferences`, для синхронизации — обернуть запись и чтение.
- Пути к файлам относительные, сервер не нужен. Сборка `dist/` подходит как `webDir` для Capacitor.
- Иконки генерирует `scripts/gen-icons.mjs` (нужен `playwright`).

## Что исправлено относительно прототипа

- Нет генерации HTML строками и `innerHTML`: только компоненты. Таблица рендерится только в виде «Таблица», дублирующиеся `tabs()` и `change`-слушатели убраны.
- «Сегодня» обновляется в полночь и при возвращении в приложение.
- id SVG-фильтров уникальные (`useId`), миниатюры упражнений строятся тем же компонентом в статичном режиме.
- Общий прогресс на главной и в достижениях всегда считается за **текущий месяц**, а не за месяц, открытый в трекере.
- Счётчик повторов и пауза больше не сбрасываются при отметке подхода или смене нагрузки, только при смене упражнения или темпа.
- Карточки «По неделям» в таблице: в оригинале CSS-правило `.wk div` ломало полоски прогресса, теперь они видны.
- Числовые поля применяют значение по Enter или при уходе с поля (как событие `change` в оригинале).
- Небольшие правки для пальцев: кнопки навигации не ниже 36 px.
- Шрифт Roboto Serif встроен в сборку, Google Fonts не нужен, поэтому всё работает офлайн.
